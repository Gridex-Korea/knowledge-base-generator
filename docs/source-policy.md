# 원문 보관 및 공개 정책

모든 프로젝트는 공개 저장소 `<name>`과 비공개 개발 저장소 `<name>-dev` 두 개를 반드시 운영합니다.
개발 저장소 이름은 공개 저장소의 전체 이름 뒤에 정확히 `-dev`를 붙입니다.

- 원문은 Source ID, 공식 URL, 발행기관, 버전, 발행일·시행일, 확인일, 페이지·절로 추적합니다.
- 수집한 PDF·HTML·데이터 등 원문 파일과 추출 전문은 비공개 개발 저장소의 `sources/`에 저장하고 Git으로 버전 관리합니다.
- 개발 저장소의 `data/source-archive.yaml`에 Source ID, 공식 URL, 보관 경로, 수집 시각, SHA-256, 버전을 기록합니다. 변경된 원문은 새 버전으로 보관합니다.
- 공개 저장소와 공개 사이트에는 검증된 지식·요약 및 출처 메타데이터를 게시하며, 원문 제공은 발행기관의 공식 URL 링크로만 합니다.
- 원문 파일, 전문 복제, 원문 embed/다운로드, 개발 저장소 경로·URL은 공개 사이트·검색 인덱스·배포 산출물에 포함하지 않습니다.
- 개발 저장소의 원문과 연구 기록은 검토 후 필요한 지식만 공개 저장소로 옮깁니다. 개발 저장소 전체를 복사하거나 Git 이력을 공개 저장소에 병합하지 않습니다.
- 공개 사이트는 공개 저장소만 빌드합니다. Cloud Storage는 비공개 보조 사본이며 개발 저장소 원문 보관을 대체하지 않습니다.
- 원문을 확보하지 못한 경우 개발 저장소에 사유와 후속 작업을 기록합니다. URL만 기록한 상태를 원문 보관 완료로 표시하지 않습니다.

## 저장소 구조

```text
<name>/                         # Public: 공개 사이트 빌드 입력
  content/                      # 검증된 지식·요약
  data/source-registry.yaml      # 출처 ID·공식 URL·버전·확인일·locator
<name>-dev/                     # Private: 반드시 별도 Git 저장소
  sources/<source-id>/<date>/    # 수집 원문 및 추출 전문, Git 추적
  data/source-archive.yaml       # Source ID·원문 URL·파일 경로·수집 시각·SHA-256·버전
  project/                      # roadmap, evidence gaps, 연구·감사 기록
  gcp/                          # 수집·운영 구성
```

예: `offshore-wind-knowledge-base`(Public) + `offshore-wind-knowledge-base-dev`(Private).
`--output ./custom-kb`를 지정하면 `custom-kb`와 `custom-kb-dev`를 만듭니다.
두 디렉터리는 독립된 Git 이력을 사용하며 각 디렉터리에서 별도로 커밋합니다.

## 수집과 공개

1. 공식 원문을 수집하여 개발 저장소 `sources/`에 저장합니다.
2. 보관 파일의 SHA-256을 계산하고 Source ID와 버전·수집 시각·경로를 보관 이력에 기록합니다.
3. 공개 Source Registry와 문서에는 같은 Source ID와 공식 URL·버전·페이지/절·확인일을 기록합니다.
4. 검증된 지식과 공개 가능한 출처 메타데이터만 공개 저장소 PR로 반영합니다.
5. 사이트·검색 인덱스·배포 ZIP에 원문 파일, 추출 전문, 개발 저장소 링크가 없는지 검사합니다.

생성기는 보관 폴더와 이력 양식을 제공합니다. 실제 원문 다운로드·체크섬 계산·사이트 빌드는 수집/배포 작업에서 수행해야 합니다.
Web Generator의 초기 ZIP은 두 저장소를 만드는 작업용 패키지입니다. 이 ZIP 전체를 공개 사이트에 배포하지 않습니다.

## 기존 프로젝트 전환

기존 단일 저장소 프로젝트는 `<name>-dev`를 Private로 준비하고 원문·연구 기록·운영 구성을 옮깁니다.
`project.yaml`의 `public`은 `true`로 설정합니다. 이전 `--private` 단일 저장소 모드는 더 이상 지원하지 않습니다.
`kbgen init ... --force`는 파일을 병합할 뿐 기존 파일이나 Git 이력을 정리하지 않습니다.
기존 원문과 내부 기록이 공개 Git 이력에 남지 않도록 확인하고 필요한 경우 깨끗한 공개 checkout을 준비합니다.
사용자 정의 Starter Vault 역시 원문을 포함하지 않는 공개용 템플릿만 사용합니다.

GitHub bootstrap은 두 저장소를 각각 생성하며 기존 origin이 있으면 대상 이름과 공개 여부를 확인한 뒤 push합니다.
개발 저장소가 Public이거나 공개 저장소에 알려진 원문/운영 경로가 있으면 실행을 중단합니다.
이 검사는 임의의 파일에 담긴 원문 내용까지 분류하지 않으므로 공개 PR에서 내용 검토도 수행합니다.
